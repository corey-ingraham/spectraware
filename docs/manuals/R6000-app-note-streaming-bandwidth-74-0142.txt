Optimizing Streaming Bandwidth
for Contiguous Capture with
R6000
This application note explains how to leverage onboard signal processing functionality in thinkRF
R6000 Real-Time Spectrum Analyzer (RTSA) to achieve the best possible streaming bandwidth with
contiguous data packets. It further explains how the settings permit the trade-off between sample
depth, bandwidth and dynamic range as required in the user’s application.

Overview
thinkRF’s R6000 RTSA supports streaming at rates up to

   •   720 Mbps with 1GigE interface.
   •   1550 Mbps with USB3 interface.
Such high speeds allow for wider streaming bandwidth of up to 25 MHz IFBW with contiguous
data.
For the ethernet connection, however, achieving speeds this high requires a network infrastruc-
ture and host computer system to sustain continuous data transfer at 500 Mbps or greater. A
network or computer system bottleneck will effectively reduce the maximum contiguous stream-
ing bandwidth.
See Table 1 to determine whether the output data configuration will be contiguous for a given
network bandwidth. To determine the contiguousness of the received data, RTSA data packets
provide a ‘discontinuity’ indicator bit which identifies for any data dropped between the received
packets. thinkRF’s libtrf API provides an example code to illustrate the usage.

Sample Size and Decimation
As the RTSA has an IQ sample rate of 122.88 MHz and a 14-bit ADC, its connection interface
will not be able to keep up with the rate at which data is produced. To achieve the best possible
streaming bandwidth, it will often be necessary to reduce the size of data samples. If the total
bitrate for a given configuration exceeds the maximum transfer rate of the R6000, the output
data stream will contain discontinuities between data packets (not within the packets).

Optimizing Signal Performance for Reduced Sample Size
When input samples are truncated using :SOURce:DIGital:DATA:SIZE {8 | 10 | 12},
it is crucial to select the appropriate reference level for the input signal. The R6000 automati-
cally recenters incoming samples in the output sample size according to the system configura-
tion. Quantitatively, this effect varies depending on the contents of the input signal of interest. A
series of examples using an input tone is shown below.
If the selected input reference level is much higher than the input signal, the resulting data sam-
ples occupy fewer of the available bits. In this scenario, the resulting signal is distorted due to
quantization. The result is that dynamic range is effectively much lower.

                                             range for small sample sizes.


Note that this effect is much less severe when larger samples are used. For example, Figure 2
shows the same configuration but with 16-bit sample depth.

Data Format Commands
The following SCPI commands affect the required bandwidth for the output data stream:

   •   [:SENSe]:DECimation (or SWEep:ENTRy:DECimation)

   •   SOURce:DIGital:DATA:SIZE
Please refer to the R6000 Programmer’s Guide for more information.
Note: Users of libtrf API do not have to manually set the decimation. For the sample depth (size), use
‘TRFBitPacking’ parameter.
